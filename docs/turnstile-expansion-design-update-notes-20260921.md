# Turnstile 拡張設計書 更新メモ (2026-09-21)

## この文書の目的

[turnstile-expansion-design.md](./turnstile-expansion-design.md) に対して行った追記・修正の背景と理由を記録する。

このメモは「何を変更したか」だけでなく、「なぜその変更が必要だったか」を後から確認できるようにするためのものである。

## 変更概要

対象文書:
- [turnstile-expansion-design.md](./turnstile-expansion-design.md)

主な変更:
1. challenge 再送に関する説明を「POST 固定の画面だけ」に限定しない表現へ修正
2. GET 画面で受け取ったパラメータを challenge 後に POST で再送する方針を明記
3. 分割テンプレート（h1/h2/body など）における challenge 配置ルールを新設
4. FuncMap 方針を「CommonFuncMap ベース前提」で明記
5. 実装チェックリストへ、hidden 項目・POST 再送・分割テンプレート完結性などの確認項目を追加
6. 実コード参照用のリンク集を追加

## 変更理由

### 1) 分割テンプレート対応を明記した理由

当初の設計書は、1テンプレート内で challenge と通常表示を切り替える構成を暗黙の前提としていた。

しかし実装対象には、`list-cntrb` 系のように複数 gtpl を順次 `ExecuteTemplate()` する構成がある。この構成では challenge 描画時に後続テンプレートが実行されないため、challenge 側テンプレート単体で HTML を完結させる必要がある。

この前提を文書化しないと、適用者が誤って challenge を後段テンプレートへ置き、表示崩れや責務分担の破綻を起こす可能性がある。

### 2) GET -> POST 再送方針を明記した理由

今回の拡張はボット対策を重視しており、challenge 再送経路を POST に統一する実装は運用上の一貫性を高める。

加えて、ハンドラーが `FormValue()` でパラメータを受け取る実装であれば、元リクエストが GET でも challenge 通過後の POST で同じ値を扱える。必要な値を hidden で引き継ぐことで、検索条件やページ位置を維持できる。

この実装方針を設計書に明示することで、適用時の判断ブレを減らす。

### 3) CommonFuncMap ベース前提を明記した理由

過去に challenge 経路と通常経路で FuncMap の差分が問題になったため、現行実装では challenge 描画を CommonFuncMap ベースで統一している。

設計書にこの前提が明示されていないと、将来の拡張時にハンドラー固有関数へ寄せた変更が challenge 側だけで欠落する事故が再発しやすい。

そのため「Turnstile challenge 経路は CommonFuncMap ベース」を設計前提として固定した。

### 4) チェックリスト拡張を行った理由

今回実際に追加対応した観点（hidden 項目の最小集合、GET画面でも POST 再送、分割テンプレート完結性）が既存チェックリストに不足していた。

チェックリストを更新することで、次回以降の適用作業を手順化し、実装漏れを防止できる。

### 5) 実装例リンクを追加した理由

設計文だけでは具体像を掴みにくい場面があるため、代表的な実装パターンごとに参照先コードを列挙した。

これにより、適用者は「どの方式を真似るべきか」を短時間で判断でき、レビュー時も根拠を共有しやすくなる。
